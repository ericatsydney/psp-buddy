## Game rules learned live (all fixed in code with tests)

1. **Hit and Away** (pilot skill id 20: Arios, Baldios; VF-25G also has it): after the attack a
   "HIT&AWAY! Move / Standby" menu appears with Move highlighted. MVP rule from the user: choose Standby.
   `act.result()` presses Down + Circle for skill-20 units; an overlay fallback (Cross, Down, Circle) remains.
   The unit's action counter stays 1 until the menu is answered; the move range is *not* always in memory (Baldios).
2. **Hover hit chance can exceed 100** (raw 105 seen, Shenlong Vulcan). `decode_hover_hit` maps 101–200 to hit 100 with
   `raw` kept. Unknown reads are polled briefly (`_hit_when_ready`).
3. **The weapon menu hides weapons** needing more will or EN than the unit has (Strike Freedom: 9 weapons, 6 rows).
   Pilot will is not decoded, so `tactics` only picks weapons whose row is certain (no earlier weapon could be hidden)
   and never a weapon with will > 100. `act.attack_menu` accepts `row < menu rows <= weapon count`.
4. **Non-P weapons cannot be used after a move** — the game shows "Requirement unmet: Post-Move" (user's screenshot,
   Force Impulse HiEnergyBeamGun). `targets_in_range` already models this with the P flag.
5. Timing: `ACT_SECONDS` 95 → 105 (hard helper cancel stays 120 s), `act.FIRE_NEEDS` 50 → 40 (real fire ≈ 25 s).
6. Re-plan: if the game refuses a weapon before any Move (`weapon`/`target`/`forecast` stage), `plan_and_act` excludes
   that slot and plans again (max 2, `excluded` in the result). Pre-action failures without a move are turn *skips*,
   not stops (`turn.BEFORE_ACTION_STAGES`).

## How to run a live trial (all scripts in ignored `local/m9-tools/`)

1. `powershell -File local\m9-tools\restart.ps1 -Label <name>`: graceful close of PPSSPP (Exit dialog Yes), checks the
   originals against the latest `backups\m9live*` manifest, new SHA-256-verified backup of SAVEDATA + PPSSPP_STATE
   (AGENTS.md), launches `navigation_handoff.py` from the repo root, writes the run folder to `local\m8-evdir.txt`.
   **Note:** it sorts backup folders by name, so `m9live9` sorts after `m9live16`; fine for the unchanged check, but rename
   the label scheme (zero-pad) before relying on "latest".
2. Wait for `navigation-ready.json` **plus about 40 s**, create `local\runtime\ppsspp-v1.20.4\app\memstick\PSP\SCREENSHOT`
   first. Three PPSSPP crashes (0xc0000005 at offset 0x864414) happened on a screenshot or read taken too early or with the
   folder missing; one launch also timed out. Saves were never affected (originals 46/46 unchanged after every run).
3. `python -u local\m9-tools\turn_loop.py <max_units> <first_sequence>` drives `turn_next` → screenshot (`shot.ps1`,
   Alt+D, t) → `plan_act` and prints one JSON line per unit; `nav.mjs` is the one-shot mailbox client.
4. Close with `restart.ps1`'s close block (or the graceful-close memory note) and re-verify originals.
